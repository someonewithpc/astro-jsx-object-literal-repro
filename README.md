# Astro JSX object literal regression repro

Minimal reproduction for a build regression when upgrading Astro 6 → 7.

Note: This repo was mostly generated by Cursor as a minimal reproduction of an error I encountered.

## Pattern

This `.astro` template expression maps a string key to JSX via an object literal:

```astro
{(layer = 'main') => ({
  main: (
    <Widget />
  ),
  other: (
    <p>Other layer</p>
  ),
}[layer])}
```

I found this pattern useful for passing multiple "slots" into a component (i.e. `{Astro.props.layers.map((id) => Astro.slots.render('layers', [id]))}`).

## Branches

| Branch | Astro | `npm run build` |
|--------|-------|-----------------|
| `astro-6` | 6.x | ✅ succeeds |
| `astro-7` | 7.x | ❌ fails |

## Astro 7 error

```
[PARSE_ERROR] Expected `>` but found `/`
    ╭─[ src/pages/index.astro:12:16 ]
    │
 12 │     main: <Widget />,
    │                   ┬
    │                   ╰── `>` expected
```

Rolldown appears to receive the object literal with un-parenthesized JSX (`main: <Widget />`) instead of the parenthesized form Astro 6 accepts (`main: (<Widget />)`).

## Workaround on Astro 7

Use a ternary chain or `switch` instead of an object literal:

```astro
{(layer = 'main') => layer === 'main' ? (
  <Widget />
) : (
  <p>Other layer</p>
)}
```

## Reproduce

```bash
git checkout astro-6
npm install
npm run build

git checkout astro-7
npm install
npm run build   # fails
```
